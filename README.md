# GymScape clan

Статический клановый рейтинг для GitHub Pages. Публичные игровые счётчики собираются ежедневно: основной запуск в 00:00 Москвы (`0 21 * * *` UTC), резервные — в 00:17, 02:17 и 04:17 (`17 21,23,1 * * *` UTC). GitHub Actions может задерживать запуск: сохраняется первый фактический снимок московской даты, последующие запуски его не меняют. Даже сильно опоздавший запуск сохраняет данные, а не пропускает день.

## Периоды и динамика

В интерфейсе три периода: **Тотал**, **Сегодня**, **Вчера**. При открытии сайта и ручном обновлении браузер читает текущие публичные счётчики из GymScape. Для этого не нужен игровой аккаунт, дополнительный сервер или секретный ключ.

- **Тотал** — все накопленные повторения на момент обновления. Если получить свежие значения не удалось, остаётся последний сохранённый снимок с его датой.
- **Сегодня** — разница текущего значения и сегодняшнего снимка по московскому времени. В день начала наблюдения или добавления игрока результат считается от его персонального стартового снимка и отмечается как неполный. Снимок после 06:00 МСК также явно отмечается как поздний: результат включает только прирост после его фактического времени. Стартовый тотал в результат дня не входит.
- **Вчера** — разница двух подходящих снимков именно за предыдущую московскую дату. Если нужного снимка нет, сайт не подставляет последний доступный день или ноль.

Общий график показывает дневной прирост всех участников текущего списка по выбранному упражнению: внутри каждого дня отдельные цветные столбцы игроков стоят рядом и начинаются от нуля. По высоте можно сравнивать результаты участников. В легенде и на графике остаются только игроки с положительным результатом хотя бы в один из выбранных дней по выбранному упражнению. Отсутствие данных не подменяется нулём. Сегодняшние столбцы ещё меняются. Разницу между снимками через несколько дней нельзя достоверно разложить по дням, поэтому она не приписывается одному дню. Такой прирост показывается отдельным блоком над графиком с фактическими границами полного интервала, суммой и результатами игроков. Новые замеры в браузере не изменяют сохранённую историю: её по-прежнему собирает ежедневный Actions.

## Учёт результатов

- `history/baseline.json` — неизменяемый стартовый тотал. Он никогда не считается дневной активностью.
- `history/daily/YYYY-MM-DD.json` — первый сохранённый снимок московской даты; повторный запуск не перезаписывает его. `captured_at` — фактическое время, `capture_delay_seconds` — задержка относительно местной полуночи, `late_capture` — завершение в 06:00 МСК или позже. Эти признаки не означают, что более ранний снимок сделан ровно в полночь.
- Дневной результат — разница соседних снимков. Первый интервал, пропуски дней и интервалы с поздней границей помечаются как неполные. При отсутствии сегодняшнего снимка сайт предупреждает об этом.
- Сброс счётчика, временное исчезновение упражнения, смена идентичности игрока или отсутствие данных не превращаются в нулевую активность либо положительный скачок.
- Планка и другие упражнения на время измеряются в секундах, отдельно от повторений. `tutorial` и `wilderness` исключены.
- Бег на месте (`labJogInPlace`) сохраняется и доступен отдельно, но по решению клана не входит в общий тотал повторений.
- Счётчики публичного рейтинга не имеют поля даты. Эти разницы показывают изменения счётчиков между снимками; поздняя синхронизация игры может перенести изменение в следующий интервал.

## Источники

`exercise_hiscores` возвращает ник, упражнение и счётчик. `hiscores_full_v2` возвращает публичный идентификатор, уровни, игровой опыт и золото. Идентификатор используется для продолжения наблюдения при смене ника. Клиентская конфигурация в `public_client.json` содержит только **publishable**-ключ, распространяемый в самом приложении; это не пароль и не пользовательская сессия.

Запрос `exercise_log` с календарной историей без пользовательской сессии вернул пустой массив. Он не используется. Источника массы тела, пульса и активной длительности нагрузки нет: калории не рассчитываются.

API не документирован разработчиком как сторонняя интеграция и может измениться. Сетевые ошибки останавливают запись нового снимка и завершают Actions с ошибкой. Старые данные остаются доступными с прежним временем снимка.

Снимок коммитится до публикации сайта, поэтому ошибка GitHub Pages не теряет собранные данные. Если публикация не удалась, workflow через 20 секунд повторяет её с тем же пакетом; повторная ошибка завершает запуск с ошибкой. Следующий запуск публикует уже сохранённую историю.

## Локальный запуск

Python 3.9+; сторонние зависимости не нужны.

```sh
python3 -m unittest discover -s tests -v
node --test tests/test_metrics.cjs
python3 scripts/build_data.py
python3 -m http.server 8765 --directory site
```

Новый стартовый снимок создаётся только при отсутствии существующего:

```sh
python3 scripts/collect.py --mode baseline
```

Дневной сбор доступен в любое время. Опоздавший снимок сохраняется с фактическим временем, без переноса на полночь или заполнения прошлых дат. Если сбор пересёк московскую полночь, запись прерывается с ошибкой: нужно повторить сбор для новой даты.

```sh
python3 scripts/collect.py --mode daily
python3 scripts/build_data.py
```

Ники находятся в `players.json`. История и автоматическая публикация — в `.github/workflows/update-and-deploy.yml`. Каждый запуск проверяет наличие снимка текущей московской даты: если его ещё нет, он создаётся, иначе остаётся прежним. Для работы публикации Pages должен использовать источник **GitHub Actions**, а workflow — иметь `contents: write`, `issues: write`, `pages: write`, `id-token: write`.

## Общий список участников

В разделе «Участники» можно добавить или убрать ник. Кнопка открывает готовую заявку GitHub Issue; её нужно отправить с любого GitHub-аккаунта. Специальных ролей или прав на репозиторий нет. Полностью анонимная запись на GitHub Pages не поддерживается.

Actions обрабатывает открытые заявки с префиксом `[roster]`, валидирует JSON и ник как данные, сохраняет результат в Git и публикует сайт. Issue закрывается после успешной публикации. Каждый запуск читает очередь, поэтому замена ожидающего запуска не теряет заявку. Повторное выполнение номера Issue не повторяет действие. На странице Issue в заголовке будет результат.

При добавлении создаётся индивидуальный стартовый снимок `history/enrollments/<issue>.json`; он не засчитывается как выполненные за день упражнения. При удалении меняется только текущий список, история остаётся. Повторное добавление создаёт новую точку отсчёта, чтобы активность вне наблюдения не попала в дневной прогресс. Для защиты от случайного раздувания списка предусмотрен лимит 200 активных участников.

В публичном репозитории расписания могут отключаться после 60 дней без активности. Успешные ежедневные снимки создают коммиты; если источник данных долго недоступен, стоит проверить статус workflow в Actions.

## Что публикуется

Только сайт, код сборщика, список участников, каталог упражнений, публичная конфигурация клиента и снимки указанных игроков. Исследовательские материалы, локальная SQLite-база, скачанный APK и файлы соседних проектов не входят в публикацию.
